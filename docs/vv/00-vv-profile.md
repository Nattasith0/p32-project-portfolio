## 2. ระบบของเรา

- ระบบนี้ทำอะไร (2–3 ประโยค): P32 เป็นเว็บสำหรับบริหารและติดตามโครงงานนักศึกษาสาขาวิศวกรรมซอฟต์แวร์ รวมข้อมูลรายวิชา การส่งและตรวจรายงานความก้าวหน้า คำขอสอบ การแก้ไข และการตรวจเล่มตามสิทธิ์ของผู้เกี่ยวข้อง ระบบเก็บรุ่นเอกสาร ผลตรวจ และประวัติ พร้อมพื้นที่ให้เจ้าของจัดการผลงานและทักษะใน Digital Portfolio โดยการเปิดให้ผู้ชมอื่นเข้าถึงจริงยังอยู่ระหว่างยืนยันนโยบาย
- ผู้ใช้หลักและผู้มีส่วนได้ส่วนเสีย: นักศึกษาในโครงงาน อาจารย์ที่ปรึกษา ผู้ดูแลรายวิชา กรรมการสอบ ผู้ดูแลระบบ นักศึกษาผู้ชม Portfolio ภายในมหาวิทยาลัย และทีมระบบที่แลกเปลี่ยนข้อมูล โดยการเปิดให้ผู้ชมอื่นเข้าถึง Portfolio ยังรอยืนยันวิธีตรวจสถานะและสิทธิ์ผู้ชม
- ผู้ใช้จริงที่จะชวนมาทำ UAT ได้: กลุ่มนักศึกษารายวิชา ENGSE212 อาจารย์ที่ปรึกษา และผู้ดูแลรายวิชาโครงงานของสาขาวิศวกรรมซอฟต์แวร์ **เป็นกลุ่มเป้าหมายสำหรับเชิญ ยังไม่ยืนยันการนัดหมายหรือผล UAT**
- การ deploy: ปัจจุบันทดสอบในเครื่องพัฒนา Windows ด้วย Next.js ที่ `http://localhost:5173`, Express ที่ `http://127.0.0.1:3001` และ PostgreSQL ฐานพัฒนา `p32_dev` โดยใช้ข้อมูลทดสอบ มีโหมดทดสอบผ่าน LAN สำหรับเครื่องในเครือข่ายเดียวกันและใช้บัญชีสาธิต การติดตั้ง production และสถานที่ใช้งานจริง **รอยืนยันและดำเนินการ**; โมดูลธุรกิจหลายส่วนยังเปิดเฉพาะ development

## 3. เอกสารที่มีอยู่แล้ว

- แบบเสนอโครงงานสำหรับ D05: มี **SE02 ฉบับลงนาม** เตรียมไฟล์ `docs/srs/proposal.pdf` ไว้ในเครื่อง ยังไม่แนบในการอัปเดตรอบนี้ และจะเพิ่มสำหรับรายการ D05 ตามกำหนดส่ง
- SRS ฉบับใหม่: **ฉบับร่าง 0.1 วันที่ 25/11/2569** อยู่ในเครื่องผู้พัฒนา กำลังทบทวนรายละเอียด ยังไม่ได้รับรองเป็นฉบับตกลงร่วมกันและยังไม่แนบในชุดส่งรอบนี้
- จำนวนความต้องการตามข้อเสนอโครงงานเดิม: เชิงฟังก์ชันหลัก **18 ข้อ (FR01–FR18)**, ข้อกำหนดร่วม **3 ข้อ (CFR01–CFR03)** และเชิงไม่เป็นฟังก์ชัน **7 ข้อ (NFR01–NFR07)** ใช้จำนวนระดับหลักตามข้อเสนอเป็นฐานของ Profile รอบนี้ ส่วนรายละเอียดที่แตกย่อยใน SRS ใหม่อยู่ระหว่างทบทวน
- RTM: มีฉบับพัฒนาในชุดระบบเต็มบนเครื่องที่ `docs/requirements-traceability.md` ระบุทบทวนวันที่ 16 พฤศจิกายน 2569 ยังต้องทวนให้ตรงกับ SRS และผลตรวจล่าสุด และยังไม่แนบในชุดส่งรอบนี้
- แบบสถาปัตยกรรม / ER: มี C1/C2, Logical ERD และ UI Flow ในโฟลเดอร์แผนภาพบนเครื่อง ยังต้องทวนกับระบบล่าสุด และยังไม่แนบในชุดส่งรอบนี้
- API spec / สัญญา: มีเอกสาร `docs/api/` และร่างสัญญา IF01–IF03 ที่ `docs/integration/contracts.md` ในชุดระบบเต็มบนเครื่อง ร่างสัญญายังไม่ยืนยันร่วมกับคู่ทีม และเอกสารเหล่านี้ยังไม่แนบในชุดส่งรอบนี้
- เอกสารประกอบในชุดระบบเต็มบนเครื่อง: `docs/permission-matrix.md`, `docs/remaining-work-checklist.md` และ `docs/phase-10-verification.md` ยังไม่แนบในชุดส่งรอบนี้

**เทคโนโลยีที่ใช้ตามข้อมูลล่าสุด:**

- Frontend: **Next.js และ TypeScript**
- Backend: **Node.js และ Express.js**

ใช้ข้อสรุปนี้ในการปรับรายละเอียดเทคโนโลยีของ SRS และเกณฑ์ NFR07 ให้สอดคล้องกับระบบปัจจุบัน

## 4. สถานะตอนนี้

- Sprint ปัจจุบันและสิ่งที่กำลังทำ: **ยังไม่ได้ยืนยันรหัส Sprint ทางการ** ติดตามงานด้วยแผน 10 ระยะและ [Trello](https://trello.com/b/2hlmppU9/p32-project-portfolio) ปัจจุบันทบทวนงานและเตรียมเอกสาร V&V ระหว่างรอข้อตกลง Login กลาง ข้อมูลคู่ทีม และกติกาบางส่วนของรายวิชา
- ส่วนที่ทำเสร็จแล้วตามขอบเขตพัฒนา: พื้นฐานระบบ บัญชี/สิทธิ์ แพ็กนำเข้าจำลอง IF01/IF02 รายงานสามรอบพร้อม PDF รับรอง ประกาศ/ปฏิทิน/เอกสาร คำขอและขั้นสอบ/ตรวจเล่มที่เปิดทดสอบ Portfolio ของเจ้าของ แพ็ก IF03 กับผู้รับจำลอง และส่วนประวัติ/ไฟล์/ส่งออก
- ส่วนที่ยังไม่เสร็จ: เชื่อมและทดสอบร่วมกับระบบจริง ขั้นส่งและตรวจรับเล่มฉบับสมบูรณ์ ช่องทางผู้ชม Portfolio จริง การบังคับกำหนดส่งตามกติกาที่ยืนยัน Performance/UAT การติดตั้ง production และเอกสารส่งมอบ การแจ้งเตือน LINE/อีเมลพักไว้
